# テスト記録

指示書 15 章のテスト要件について、**何を・どの方法で確認したか** と **未検証の項目** を明記します。

## 自動テスト

| 種類 | コマンド | 内容 |
|---|---|---|
| ユニットテスト | `npm test` | GPS 除去 (JPEG / HEIC / XMP / 動画)、撮影日時の読み取り、ファイル形式判定 |
| DB・権限テスト | `npm run test:db` | 全マイグレーションを適用し、RLS・招待・アップロード・通知など 50 項目以上を検証 (素の PostgreSQL 16 に Supabase の auth / storage を模した最小スタブを用意して実行) |
| ブラウザ E2E (モック) | `npm run test:e2e` | iPhone 13 / Pixel 7 の画面サイズ・タッチをエミュレートし、Supabase API をモックして主要画面と一括アップロードを検証 |
| 型チェック・ビルド | `npm run build` | TypeScript の型エラーがないこと、本番ビルドが成功すること |

GitHub Actions (`.github/workflows/ci.yml`) で、push のたびに型チェック・ユニットテスト・ビルド・DB テストが実行されます。

### ブラウザ E2E の実行方法

```bash
VITE_SUPABASE_URL=http://mock.supabase.test VITE_SUPABASE_ANON_KEY=test npx vite build
npx vite preview --port 4173 &
npm run test:e2e   # スクリーンショットは e2e/screenshots/ に保存
```

## 既知の制約

- **Web 版の Live Photos**: ブラウザには静止画部分しか渡されないため、動きのある部分は保存されません。
- **バックグラウンドアップロード**: ブラウザの仕様上、アプリを閉じる・画面をロックするとアップロードは停止します (画面スリープ防止を実装済み。再開時は TUS により続きから送信)。ネイティブアプリ化 (Capacitor) で改善可能です。
- **HEIC の表示**: Chrome / Android は HEIC を表示できないため、一覧・拡大表示は**アップロードした端末で生成した JPEG** を使用します。iPhone (Safari) からのアップロードは端末内で JPEG を生成できるため、どのブラウザでも表示されます。
  - PC の Chrome などから HEIC ファイルをアップロードした場合、変換ライブラリ (heic2any) が内部で `eval` 相当の処理を使うため、セキュリティヘッダー (CSP) により変換がブロックされ、サムネイルがアイコン表示になります (オリジナルは保存・ダウンロード可能)。
  - セキュリティを優先してこの設定にしています。変換を有効にしたい場合は `vercel.json` の `script-src` に `'unsafe-eval'` を追加します (XSS 対策が弱まるため非推奨)。
- **端末の写真との照合**: ブラウザはスマホの写真フォルダを直接読めないため、照合したい写真をユーザーが選ぶ必要があります (PC はフォルダ選択可)。比較は「見た目の指紋」で行うため、形式の変換や再圧縮には強い一方、ほぼ同じ構図の連写写真は同じ写真と判定されることがあります。また、照合時に選ばなかった写真は「端末にない」とみなし、保存済みの記録を取り消します。この機能の追加前にアップロードされた写真は、照合のたびにサムネイルから指紋を計算するため時間がかかります。
- **動画のサムネイル**: その端末で再生できない形式 (例: 一部 Android での HEVC) はサムネイルが生成されません。
